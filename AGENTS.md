- Respond short, precise, and concise.
- If you didn't add a test, you didn't fix a bug. Every bug fix must include a reproducible test that fails without the fix and passes with it.
- Specs live in specs/. When implementing a big feature, create specs first then implement. Each spec is tightly scoped. When a spec is completed, record the outcome and archive it.
- Layout: the module root is the contract, with explanation.go for the explanations (spec 009), report.go for the report of an organization (spec 010), and reach.go and consent.go for consent: the scope of an action, the cover rule and the weight of an answer (spec 011, wave 1; its shared arithmetic is in estimate/consent.go, its reading of the input in engine/featurize/reach.go); authorizer/ the authz vocabulary; api/openapi.yaml the HTTP surface; estimate/ the estimators (spec 008); stub/ and conformance/ (spec 006); engine/ with kernel/, gp/, featurize/, store/ (spec 004); client/, server/, cmd/limend (spec 003); cmd/limen, the replay command, and importer/topos, its reader of Topos session logs (specs 007, 008). The hook command of spec 005 and a store that more than one server shares are not built. Anything not yet in the tree starts from its spec.
- Limen predicts; the decision point decides. Ceilings, review draws and the verdict applied belong to the decision point (latere.ai/x/pkg/verdict.Decide) and reach Limen only as a recorded Decision.
- The root package imports the standard library and latere.ai/x/pkg/verdict only; a new dependency goes in a subpackage (gonum lives under engine/), with a depcheck decision in .lateregate.yaml.
- The invariants of specs/001-architecture.md are not negotiable in a change: a deterministic deny is final, a failure asks, the review probability is the decision point's and drawn once, an unknown action is an ask (every accepted profile puts 1/2 in the ask band), an action's input is never stored, an answer's role is derived from the decision, a key names one action, Forget removes everything of a subject in an org.
- A JSON field name never changes; a new field is optional; receivers ignore unknown fields; api/openapi.yaml changes in the same commit as the Go type it describes.
- Commit frequently, one small scope diff at a time. Push to main once a full batch of work is complete and verified.
- Leftovers are cleaned up in follow-up commits.
- Target a high quality outcome, >90% coverage, each feature verified via an e2e test.
- Write in audience language: documents aim at user value and usage, the API surface aims at builder precision, code comments aim at technical precision. American English, no em dashes.
- Technical user surfaces for developers and operators (README, docs/, SECURITY.md, templates, API error messages, prediction reasons, CLI output) follow the ASD-STE100 writing rules in CONTRIBUTING.md "Writing for users", with the terms of docs/terms.md and no others. A website or product page is not STE: write it in the audience's language, not in engineering terms.
- This repository is meant to be public. No Latere hostname, token, or internal reference anywhere but as a default or an example. A hosted platform that builds on it lives elsewhere and is one consumer among any.
- The research behind the design is arXiv:2605.19151, with its reference code and Lean proofs at github.com/changkun/trustcalib; cite the proposition a change to the arithmetic follows.
- The shared components are public Go modules: latere.ai/x/pkg (github.com/latere-ai/pkg), with verdict, authz and authkit, and the gate latere.ai/x/ci-gate (github.com/latere-ai/ci-gate). Topos (github.com/latere-ai/topos) is the first decision point; its internal/decisions package is the client side of this API.
- Every sentence is written for one reader (user, contributor, developer) and the register follows the reader; an error has one code, one fixed user sentence in `message`, and one developer detail in a separate field. The rule and the review checklist: https://github.com/latere-ai/pkg/blob/main/docs/writing/registers.md
